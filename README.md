### 2024/03 - 2026/08 : 株式会社プロクラ

職務: バックエンド、フロントエンド

業務委託として参画。家づくりチャットサービスのフロントエンドとバックエンドを担当。アプリ立ち上げ後あたりから参画。WEBとFlutterのアプリが存在しており、WEB側のエンジニアとして稼働。

#### 担当業務
- Next.js, React, GraphQL, TypeScriptを用いたフロントエンドの開発  
- NestJS, Prisma, GraphQL, TypeScriptを用いたバックエンドの開発
- ライブラリの破壊的変更や仕様変更に対応する実装およびバージョンアップ対応
 
#### 習得したスキル
- NestJS, Prisma, TypeScriptを用いたバックエンド開発
- バックエンドのテスト駆動開発
- 日次バッチなどの大量のデータを走査する処理で、メモリや時間計算量を考慮する実装
- 時間計算量やメモリの使用量に配慮した実装。O($n^2$)以上はできるだけ避ける。indexでのアクセスや辞書型を利用するなどして、対応できる課題にはO($1$)で済むように実装
- SOLID原則やクリーンアーキテクチャに則った開発
- 外部API(Maps JavaScript APIなど)を使用した実装、およびドキュメントで仕様の調査 
- client-presetを用いてFragment MaskingしたFragmentしたColocation。フラグメントとコンポーネントをカプセル化し。これによりtypenameとidの取得忘れを防ぎ、キャッシュが正しく機能するように担保する
- 状態管理にApolloのキャッシュを活用することで、アプリ全体の読み込み速度を短くする設計方針
- GraphQLのID設計をrelayパターンで実施
- Conventional Commitsに則ったコミットの命名規則
- フロントエンドは依存関係だけテストをして、内部実装の変更の影響が出にくくし、高速で開発
- Copilot Agent Modeを使用した開発 
- 大きな機能は使用できる環境を制限した上で、開発。つまりどんどんデプロイしていくが、本番では使えずにstgでは使用できるといった形
- 基本的にレビューをせずにどんどんマージしていく開発フロー
- GitHub Issuesを用いたチケット管理

#### コメント
特に開発手法は決まっていない中での開発。GitHub Issuesを用いたチケット管理を行い、フロントエンドに関してはレビューはせずにどんどんマージしていく開発フロー。正社員1人と私の2人で分担して開発。要件をBizやPMなどから伺い、毎日朝会やSlackで適宜仕様の確認を取りながら進めていた。Flutterアプリもあるサービスなので、リリースタイミングを揃えるためコミュニケーションを取りながら開発を進めていた。
